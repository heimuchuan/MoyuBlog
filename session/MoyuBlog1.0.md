## 一、项目概述
- **项目名**：CampusBlog = 个人博客 + 校园智能问答系统
- **定位**：练技术的全栈项目，兼顾实用（博客 + 新生入学/校园生活咨询入口）
- **技术栈**：Next.js 14 (App Router) + TypeScript + Prisma + PostgreSQL + pgvector + NextAuth + RAG + Tailwind CSS

## 二、功能规划（按优先级 P0/P1/P2）
| 模块 | 核心功能（P0） |
|------|------|
| 前台 | 文章列表（分页/时间排序）、文章详情（Markdown+代码高亮）、分类/标签筛选、关于我、智能问答入口 |
| 后台 | 管理员登录(NextAuth)、文章增删改查、分类管理、知识库管理（上传PDF/Word/TXT自动切片入库） |
| 增强(P1/P2) | 全文搜索、评论(Giscus)、访问统计、暗色模式、RSS、SEO、图片上传、草稿箱 |

## 三、技术栈选型
框架 Next.js 14、语言 TS、样式 Tailwind、组件库 shadcn/ui、ORM Prisma、数据库 PostgreSQL+pgvector、认证 NextAuth、Markdown(react-markdown+remark-gfm)、代码高亮 shiki、文档解析 pdf-parse/mammoth、嵌入模型 text-embedding-3-small 或 bge-m3、大模型 GPT-4o-mini/DeepSeek-V3/智谱GLM、部署 Vercel+Neon

## 四、数据库设计（Prisma Schema）
6 张表：`User`(管理员)、`Post`(文章)、`Category`(分类)、`Tag`(标签)、`KnowledgeDoc`(知识库文档)、`KnowledgeChunk`(切片，含 `@db.Vector(1536)`)、`QALog`(问答记录)

## 五、目录结构
Next.js App Router 标准结构，含 `app/page.tsx`、`app/posts/[slug]`、`app/chat`、`app/admin/**`、`app/api/**`、`lib/`(prisma.ts/auth.ts/document.ts/rag.ts) 等

## 六、API 接口清单
登录、文章 CRUD、分类、知识库上传/列表/删除、`POST /api/chat` 等

## 七、RAG 核心流程
上传PDF → pdf-parse解析纯文本 → 切片(500-800字/重叠100字) → embedding生成向量 → 存pgvector → 用户提问向量化 → 相似度搜索Top-5 → 拼Prompt → 大模型生成 → 返回答案+引用来源

## 八、开发步骤（4周计划）
- 第1周：搭骨架 + 前台展示
- 第2周：后台 + 登录
- 第3周：RAG知识库（核心）
- 第4周：前端问答界面 + 打磨

## 九~十二

```
[00:00.00]窗外的麻雀 在电线杆上多嘴

```

把每行的时间 `分:秒` 换算成**秒数**，写成：

```ts
lyrics: [

]
```

`time` 是这一句开始播放的秒数，播放时当前句会**自动高亮**。

**3. 往 playlist 数组里加歌**

```ts
export const playlist: Song[] = [
  {
    url: "/music/晴天.mp3",
    title: "晴天",
    artist: "周杰伦",

    title: "...",
    artist: "...",
    lyrics: [...],
  },
];
```

加多少首都可以，播放器会自动显示「上一首 / 下一首」按钮和 `1 / N` 计数，播完自动切下一首。

## 1. 音乐播放器自动下载（最省事）

网易云、QQ音乐、酷狗等本地客户端，播放歌曲时通常会**自动在安装目录的歌词文件夹里下载 lrc**。不同软件位置不同，可以搜一下文件名：

- 网易云：`C:\Users\你的用户名\AppData\Local\Netease\CloudMusic\...` 下的 Cache / Lyric 文件夹
- QQ音乐：安装目录下的 `Lyric` 文件夹

很多是 `.qrc`、`.krc` 等加密格式（网易云是 lrc，QQ音乐是 qrc，酷狗是 krc 加密的），**只有标准 `.lrc` 能直接用**。

## 2. 歌词网站搜索下载

搜「歌名 + lrc 下载」，常见站点：

- 歌词千寻、Vagalume、歌词窝等
- 下载后得到 `.lrc` 文件，改文件名跟 mp3 一致即可

## 3. 手动创建（一定能用）

`.lrc` 就是个文本文件，用记事本就能写。格式：

```
[00:00.00]作词：方文山
[00:12.50]窗外的麻雀 在电线杆上多嘴
[00:24.80]你说这一句 很有夏天的感觉
```

保存时：**另存为 → 文件名 `.lrc`，编码选 UTF-8**，放在 mp3 旁边，同名就行。

## 小提示

我的解析逻辑是兼容标准的 LRC 时间标签（`[分:秒]`），所以：

- 标准 `.lrc`（网易云下载的多是这种）✅ 直接用
- QQ音乐的 `.qrc`、酷狗的 `.krc` ❌ 是加密的，不完全兼容，不建议用
- 有 `[ti:]` `[ar:]` 标签会自动读歌名/歌手，没有也不用管

## 时间戳的问题

AI 生成的是**歌词文字**，它不知道每句歌在真实音频里第几秒唱到。而我的播放器是靠 `.lrc` 里的时间戳（`[00:12.50]` 这种）来做「当前句高亮」的。

所以有两条路：

**做法一：纯文字（最简单，但不能逐句高亮）**

把所有歌词直接排成一页显示，不跟着播放进度走。这最省事，但体验弱一点。

**做法二：带时间戳（能跟随播放，但时间要自己估）**

让 AI 按 LRC 格式给每句编一个大致的时间点，比如每句间隔 5 秒：

```
[00:05.00]第一句歌词
[00:10.00]第二句歌词
[00:15.00]第三句歌词
```

能高亮，但 AI 估的时间不会和真实歌曲完全对齐，会有点偏差。

## 目前的问题

我现在的解析器**只认带时间戳的行**，纯文字歌词（做法一）会被忽略，歌词卡会显示「暂无歌词」。

所以如果你打算走 AI 生成歌词这条路，建议我帮你加个**降级支持**：识别到某首歌的歌词是纯文本（没有时间戳）时，自动按顺序显示出来（不逐句高亮，或按固定间隔高亮）。

要我加这个吗？加完你就可以放心用 AI 生成纯歌词，直接保存成 `.lrc` 也能正常显示了。

## 最推荐：从播放器/歌词源直接拿（不是从音频生成）

你已经有 mp3 了，绝大多数中文歌网上都有现成带时间戳的 lrc，直接下载最准，不用自己生成。搜索「歌名 + 歌手 + lrc 下载」即可，之前说的歌词千寻等站点都行。

## 从音频文件本身自动生成歌词

靠**语音识别（ASR）**来听歌写词，这类工具：

- **剪映 / 必剪**：导入音频，用「识别字幕」功能自动生成歌词，可导出字幕文件
- **网易云音乐**：部分歌曲上传后能识别
- **Whisper**（OpenAI 开源）：本地/API 转写音频，能导出带时间戳的 SRT，再转 lrc

**但要注意**：语音识别听歌，中文歌词**准确率不太高**（尤其带伴奏、和声、Rap 的），时间戳也可能有偏差，效果远不如网上下载现成的。
